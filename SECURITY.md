# Data safety and security design

Android photo/video library access and legacy shared-storage read/write permissions are blocked in `app.json`, including the `READ_MEDIA_IMAGES` declaration inherited from `expo-screen-capture`. Settler uses the system document picker for backup imports and app-private files with URI grants for sharing. Screenshot blocking uses Android's `FLAG_SECURE` and does not require photo-library access. Permission removal is verified in the packaged release manifest, rather than only in Expo configuration.

Backup format 1 is a JSON envelope containing app version, schema version, UTC creation time, INR/integer minor-unit/local-date metadata, all named financial tables and preferences, and SHA-256 over the serialized payload. The digest detects accidental corruption; it is not an authenticity claim. Lock secrets are excluded. Only exact current schema backups are accepted; older database installations upgrade transactionally before creating a backup. Unsupported backup versions require the corresponding app version to open and re-export them. No arbitrary SQL is imported and merge is not supported.

Replace restore requires a reviewed summary and explicit confirmation. A persistent pre-restore backup is written before changing data. Restore validates a staging database using the same constraints and diagnostic checks, then replaces the live tables inside one SQLite transaction, with foreign-key checking before commit. Failure rolls back. App routes are gated during replacement. Recovery copies remain in the private documents directory and can be shared from the data screen. They contain sensitive unencrypted data unless the user chooses encryption; device storage protection is not database encryption.

Optional encryption uses audited Noble AES-256-GCM and PBKDF2-HMAC-SHA256 (600,000 iterations), a fresh 16-byte salt and 12-byte nonce generated by Expo Crypto. The fixed envelope version/algorithm identifiers are authenticated as additional data. Passwords are never persisted; losing the password makes the file unrecoverable. Length and KDF parameters are bounded before derivation. Decryption and all validation happen before replacement. The unencrypted SHA-256 digest is inside the encrypted plaintext. Plain CSV and plain backups expose financial data to the chosen share destination.

The optional app lock uses a salted PBKDF2 verifier in SecureStore, device-only accessibility, at least six digits, persistent exponential attempt delays, and a global route gate. Passcode change/disable requires the current passcode. Biometric authentication requires strong enrolled hardware and an authentication-bound SecureStore token that the OS invalidates when enrollment changes; the app passcode remains the fallback. Biometric credentials are not used as the only recoverable verifier. Background content is hidden immediately; relock intervals are configurable and checked on resume. Cold launches always lock. Screen-capture protection is best effort and does not promise protection against a compromised OS. This is an access gate, not SQLite encryption. There is no passcode reset that silently destroys or unlocks data; create and retain an external backup before enabling the lock.

Migrations retain explicit versions and execute together with conversion in a transaction. A SQLite backup is made before upgrading an existing database where the native backup API is available. Failed migrations preserve the database and show a retry/recovery message. Integrity diagnostics are read-only: financial errors require review; no silent repair occurs. Device-native sharing, biometric prompts, background privacy and interrupted restore must still be tested on both platforms.

Export uses the [official SheetJS React Native writer](https://docs.sheetjs.com/docs/demos/mobile/reactnative/) (0.20.3), with numeric amounts and literal string cells. No workbook formulas or hyperlinks are generated from user text. CSV prefixes dangerous leading formula characters and quotes every field. Workbook sheets contain selected transactions, referenced names and currency-separated monthly totals; they are exports, not backups. Shared files remain in private cache so recipients can read Android content URIs; files older than 24 hours are pruned on a subsequent export. Recipient copies cannot be recalled. Recovery copies persist until the user manages app storage.

The biometric enrollment behavior follows [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/). Face ID needs a development/native build with its permission plugin and cannot be fully verified in Expo Go. Native driver, OS authentication and screenshot/privacy behavior require real devices.

Dependency review: npm audit currently reports 34 advisories (12 moderate, 22 high), including Expo/React Native, screens, worklets, sharing, datetime picker and tooling dependencies. Suggested fixes include major downgrades or SDK changes; these were not applied blindly. A separate SDK-compatible dependency upgrade and real-device regression pass remain necessary before treating this as release-ready. The cryptography and SheetJS dependencies are pinned in the lockfile. Audit output is not proof that every reachable runtime path is exploitable or safe.

MVP v2 receipts use the system document picker with private cache copies and persistent app documents. JPEG/PNG/PDF signatures, UUID filenames, attachment counts and file sizes are validated. Receipt metadata commits atomically with the ledger; newly copied files are removed on a failed commit. The device-local receipt table is excluded from financial backups and cloud sync; matching ID/creation-time links survive same-device restore. Picker/share background transitions preserve forms behind the privacy cover, and image previews close when backgrounded or locked. See [MVP_V2.md](MVP_V2.md) for the required physical-device checks and backup limitations.

Voice entry uses on-device recognition only, with Android 13+ installed-locale checks and a fail-closed iOS selected-locale guard applied by postinstall. It does not persist audio or upload dictation transcripts. Reviewed expense drafts are ordinary financial transactions and participate in cloud sync only when enabled. Microphone permission is required; broad media permissions remain blocked. Recognition aborts on background/lock/blur. Expense PDF/Excel exports contain sensitive financial details and notes; the chosen recipient receives a plain copy. PDF uses escaped local HTML with no remote resources; Excel preserves literal text cells and currency-separated numeric daily/weekly/monthly totals. Export limits fail explicitly rather than truncating history.
