# Pocketbook interface

The audit found a five-tab hierarchy, a decorative balance hero, duplicated account and category reports on Home, large bordered cards around individual rows, and required descriptions in transaction entry. Everyday entry, history, budgets and accounts now have four tabs. Reports and settings remain reachable from Home; cards, loans, recurring rules, net worth and ledger tools retain their existing secondary routes. No financial feature or record was removed.

The visual system uses native system type, soft neutral light surfaces, charcoal teal dark surfaces, one restrained teal accent, accessible positive/negative colors and tabular monetary numerals. Shared spacing, typography, corner, border and motion tokens live in `src/design/tokens.ts`; themed colors are centralized alongside tokens and selected by `src/components/ui.tsx`. The latest design direction adds a teal gradient balance panel, rounded section surfaces and softly tinted icon backgrounds. Transaction and account lists retain clear separators for scanning. Account rows separate assets and liabilities; net worth is explicitly separate.

Home prioritizes active asset balance, current-month income and spending, one Add transaction action, configured budget progress and recent activity. Charts and the full account list remain in their destinations. Transaction entry starts with numeric amount, then type/category/account/date. A compact icon grid selects categories. The most recent eligible account is the default. Optional description and notes are collapsed; an omitted description saves the category name (or Transfer), preserving repository validation and exports. Existing descriptions and notes are preserved while editing. Concurrent submit taps are guarded; validation and save failures stay inline. Successful saves/deletes show a short live-region message on the destination.

History defaults to the current month, preserves server-side SQLite search, stable pagination and all prior filters, and provides month navigation plus a bottom sheet for advanced filters. Clear restores all-date history; the date scope is labeled. Reports show two main visualizations; additional trends remain in expanded detail. Empty charts never fabricate data.

Transactions now offers List and Calendar tabs. The calendar uses a Monday-first local-date grid with today and selection states, income/expense/transfer markers, filtered monthly totals and day selection. SQLite groups all matching active transactions by date, independently of list pagination; transfers contribute activity markers without inflating income or expenses. Calendar and list share search and filter validation. Month navigation and filter changes reset day selection. Clearing filters restores all dates in List, while Calendar stays scoped to its displayed month. The title, Add action, feedback, controls and calendar all belong to the FlatList header and scroll with the results in both modes. There is no fixed or sticky Transactions header. The existing spacing above List/Calendar, bottom spacing and hidden scroll indicators are retained.

All shared screens begin directly below the top safe area with no extra top padding or header bottom margin. Titles align to the top of the header row, with the standard section gap below them. Scrolling content disables automatic iOS inset adjustment because the outer safe-area container handles it. Home inherits this compact header, with 44-point report/settings controls, a fitted balance amount and two consistent monthly summary cards. An explicit 24-point spacer separates the balance card and summary cards. Recent activity sits in a single rounded surface with separators between rows. Amounts fit narrow screens, and first-time users get an Add account action before transaction entry. Budget loading and retry states remain visible.

`src/components/Depth.tsx` supplies native layered surfaces, perspective icon tiles and wallet, coin, receipt, chart, calendar, shield and card illustrations. Home, Accounts, Budgets, Settings, category selection, transaction icons, the calendar and shared empty states use these primitives. Card extrusion is reserved within layout so it cannot consume section spacing. Financial figures and date controls stay flat and readable; the artwork has no financial values and is excluded from accessibility traversal. Shared cards and buttons have modest elevation and beveled edges. Selected controls add a short Reanimated perspective press. Only Home's wallet illustration loops; it pauses on navigation blur/background, cancels on unmount and respects reduced motion. Other illustrations stay static. No GL renderer or additional package is required. Native appearance and animation performance still require device QA.

Reanimated is already installed with the SDK-compatible worklets package. Expo's Babel preset configures the plugin: https://docs.expo.dev/versions/v57.0.0/sdk/reanimated/. Reanimated covers shared screen headers and section reveals, button/row/category presses, tab focus highlights, transaction mode changes, optional details, confirmation feedback, sheet presentation/dismissal and budget progress. Timing transitions use system reduced-motion preferences. Recent Home rows use a capped stagger; paginated history keeps only press feedback to avoid animating a large list. No per-row entering animations run across paginated history. Forms retain native keyboard avoidance and safe areas; controls retain comfortable touch targets and dynamic type.

## Verification limits

TypeScript, ESLint, accounting/SQLite/cloud regression tests and Android/iOS production bundle exports are the automated checks. No usable simulator or attached device is available in this environment: native layout, keyboard behavior, screen-reader focus, light/dark appearance, enlarged text and animation frame performance require device QA before release. The changes are working application code, not static mockups. In device QA, cover ordinary expenses, income, transfers, card interest/fees, editing/deleting, month/search/filter reset, budgets, archived accounts, app lock and cloud recovery. Confirm dark status-bar contrast, Android back dismissal, iOS safe areas, reduced motion and long labels/amounts at large font sizes.

The final refinement uses an Overview heading with a contextual month and compact labeled report/settings actions. Budget edit/delete and comparison controls are secondary disclosures. Sheet close, apply and cancel all finish a brief opacity/translation transition before dismissing; native back follows the same path. The account default uses the most recently updated eligible transaction rather than its financial date, so backdated entries do not select an older account accidentally.

Automated verification: 49 passing tests, TypeScript and ESLint clean, Android and iOS Hermes production exports successful. The current dependency audit reports 34 advisories (12 moderate, 22 high); see SECURITY.md for release limitations.

## Launch branding and onboarding

`assets/icon.png` is the source for the app icon, iOS icon, Android adaptive foreground, native splash and welcome image. The native launch screen uses the SDK-compatible `expo-splash-screen` config plugin, centered at 180 points with light/dark backgrounds. Auto-hide is held until SQLite startup and secure-lock loading finish (or expose an error); it does not wait for cloud/network access. Native errors remain reachable rather than being covered indefinitely by splash.

A three-step, skippable introduction explains accounts, transaction tracking and optional cloud storage. Completion is saved under `pocketbook.onboarding.v3` in AsyncStorage. It is independent of financial tables and backups. The introduction stays inside the app-lock boundary; it cannot bypass an existing passcode. A failed completion write leaves an inline retry message. Welcome and local database loading show the supplied icon within the application as well.

Native icon and splash assets are baked into the binary: create and install a new iOS/Android build after changing them; Metro reload does not replace the installed icon or launch storyboard. Use a cold launch for splash verification. Full Xcode and signing/device setup are required for `npx expo run:ios --device`; alternatively use a configured EAS build. Do not uninstall an installation containing financial records merely to refresh branding. Expo Go does not reproduce a standalone app's icon or launch-screen behavior; see https://docs.expo.dev/versions/v57.0.0/sdk/splash-screen/.

The updated introduction uses native perspective artwork with Reanimated rather than a Three.js renderer: wallet body/clasp/card layers, a budget receipt and cloud/privacy shield. Shared UI-thread values animate depth, tilt, floating, shadow and card lift; tapping the artwork adds a short interaction. Loops cancel on unmount and pause in the background, with static art for reduced motion. The versioned completion key makes this redesigned introduction visible once to existing installations without touching financial data. Device rendering and frame-rate still require native QA.

## Navigation lifecycle fix

The captured pre-mount warning originates in Expo Router 57.0.25's `fork/useLinking.native.js`: its initial URL promise invokes `NavigationContainer`'s state callback before commit. `scripts/patch-expo-router.cjs` wraps only that delivery, queues it until a mount effect, and drops callbacks after disposal. Handled initial links still clear tracking; deep-link state resolution is unchanged. The patch runs during `postinstall`, is repeatable and fails with a review message if upstream code changes. It does not suppress LogBox warnings. See the upstream reproducer: https://github.com/expo/expo/issues/49378.

Onboarding storage loads use effect-local cancellation; completion writes check mount status before changing UI state. These changes preserve onboarding completion and all financial records. Navigation regression tests exercise a URL promise resolving before commit, post-unmount callbacks, handled routes and Strict Mode effect replay. Restart Metro with a cleared cache after applying the dependency patch so the modified Router module is transformed.

Each introduction page now has a different main subject: wallet/cards, a layered budget board with receipt, and a vault with cloud/privacy shield. The shared perspective, floating and tap animation values animate each scene; the wallet appears only on the first page. Updated native Android launcher resources are regenerated from the provided artwork; the adaptive foreground path is `assets/android-icon-foreground.png`, a copy of `assets/icon.png`.
